# The Laser workspace

Contents of `workspaces/laser`; the rules are in packages/CLAUDE.md and the root CLAUDE.md. The steps are in `docs/progress/laser.md`. Keep this list current when you add or change a file here.

- `src/index.ts`: the plugin. With `?laser` (flag.ts) it mounts the page; without it, the placeholder it was.
- `src/flag.ts`: the `?laser` switch (as Design's `?combine`: kept for the tab, `?laser=off` clears it), off until Ben releases it.
- `src/page.ts`: the Laser page (L1a, L1a2). Lists Design's flat shapes through the registry (`objectsOf("design:outlines")`, Design's representations.ts `DESIGN_OUTLINES`) and delivers each as an exact outline; never reads Design's code or copies its shapes into the project. The project keeps only `LaserData` (bed, gap, parts turned off; a sheet thickness is kept but has no box until something uses it). The view is flat (flat-view.ts) over the shared viewport's empty 2D view (`viewport.showImage(null)`, given back with `clearImage()` on sleep and unmount, so Design's body and camera return as they were); the kernel is asked nothing. Save SVG / Save DXF. Styles: `src/styles/laser-page.css`.
- `src/flat-view.ts`: the flat view (L1a2): an SVG drawing over the viewport, the bed as an outlined sheet with a ruler (lines across it, numbers below and left), each part by the same path data the saved SVG file gets (`flatScene` in page.ts), the bed and the parts named. It only slides and zooms (drag, one finger, wheel, pinch, + − 0 and the arrows); its own row of buttons (Zoom out, Zoom in, Fit) in the 3D row's look, the 3D row hidden meanwhile (the view is put straight after the 3D canvas and the style sheet hides the `.view-controls` after it). Nothing is drawn before the page's first `show`; a fitted view fits again when its size or a card's (the parts list, a phone sheet) changes; hidden while the host says `data-drawing="off"` (the second pane's "Coming soon"). Styles: `src/styles/laser-flat.css`.
- `src/view-box.ts`: the flat view's camera, pure: the one drawing rule (bed mm to screen px), Fit inside margins and clear of cards lying over the view (the parts list), zoom about a point with limits, sliding with the bed kept in sight, the ruler's 1-2-5 steps, the wheel's rate (the 3D view's), whether a name fits.
- `src/sheet.ts`: the bed and the layout (rows from the lower-left corner, `gap` between parts and from the edges, a part that doesn't fit left off with why), exact moves of outlines, and the sheet's SVG (the page is the bed in mm; each part's path data and box read from core's public `outlineToSvg` by `outlinePath`, so the arc maths stays in core until K1).
- `src/dxf.ts`: the sheet as R12 DXF in mm: closed POLYLINEs with bulges (arcs exact), CIRCLEs, on layer CUT.
- Tests: `test/sheet.test.ts`, `test/dxf.test.ts`, `test/page.test.ts` (happy-dom), `test/flat-view.test.ts` (happy-dom), `test/view-box.test.ts` (every number worked by hand), `test/flag.test.ts`. A test never compares two elements with `assert.equal` (a failure prints the whole page and runs the test out of memory): compare `a === b` with `true`. Browser check: `apps/fission/e2e/laser-page.mjs` (in `npm run e2e`).
