# Accounts database

The optional accounts' database (Supabase: PostgreSQL with row level security). Designs are never stored here. Read with the root CLAUDE.md; the app side is `packages/account` and `apps/fission/src/account.ts`.

- `migrations/`: the schema, applied in name order by the Supabase CLI (`supabase db push`). Never edit a migration that has been applied to the live project; add a new one. Every public table gets row level security and starts by revoking Supabase's default grants to `anon` and `authenticated`; grants are column by column where a person may change anything.
- `migrations/20261104000000_accounts.sql`: `profiles` (the email choice, unticked by default, with the time it last changed as the consent record), `plans` (free/pro/team, written only by the server), `ai_allowance` (never read by the browser; `my_allowance()` gives the whole percentage used, rounded down, at most 100), `my_data()` (everything kept about the person), `delete_my_account()` (removes the sign-in and every row through the foreign keys), and the trigger giving a first sign-in its rows.
- `migrations/20261105000000_payments.sql`: Pro through Stripe. `billing` (a person's Stripe customer, subscription and its status; never read by the browser), `plans.cancels_at_period_end`, and four functions only `service_role` may run: `billing_customer`, `link_stripe_customer` (keeps the first if two checkouts race), `set_plan_from_stripe` (active, trialing and past_due are Pro, every other status free, Team untouched; false for an unknown customer) and `forget_billing`. `delete_my_account` now refuses while a Stripe customer is linked (the billing function deletes it at Stripe first), and `my_data` shows the Stripe link.
- `functions/billing/index.ts`: the only code that talks to Stripe (a Supabase Edge Function, one file with no imports so it can be pasted into the dashboard; deployed with Verify JWT off, since each route checks the caller itself). Routes `checkout`, `portal`, `delete-account` (Stripe customer deleted first, so nothing is charged after) and `webhook` (signature checked, the subscription read back from Stripe rather than trusted from the event, a subscription with no account left is cancelled). TEST MODE ONLY: a live key or live event is refused unless the secret `ALLOW_LIVE` is `yes`, which waits for the lawyer's review and the hosting move. Secrets: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_MONTHLY`, `STRIPE_PRICE_YEARLY`, `STRIPE_COUPON_FIRST_YEAR`. Tested in node by `packages/account/test/billing.test.ts`.
- `migrations/20261105120000_my_designs.sql`: `designs` (each person's kept designs: file text up to 5 MiB, a picture up to 32 KiB as an image data: address, the workspace tag, revision), closed to the browser except through `save_design` (sizes, the person's space of 200 designs and 20 MiB, the revision last seen; answers saved/changed/gone/too-big/full/off), `my_designs`, `get_design`, `delete_design`, `delete_my_designs`, `my_design_space`; `profiles.keep_designs` (on by default); `my_data()` rebuilt from parts (payments' Stripe link is now `my_data_part_payments()`): every `my_data_part_<name>()` made by the migrations' owner adds its keys, so a later feature adds a part instead of replacing it. `test/test_designs.py`: other people can't list, read, change or delete, 0.9×/1.1× of every limit, two devices, the parts.
- `migrations/20261105180000_design_versions.sql`: `design_versions` (account features 2: the copy each `save_design` replaces, kept when it differs and the newest is 10 minutes older, the newest 20 per design, deleted with the design). Versions count in the 20 MiB but never cost a save: whether a save fits is decided by the designs alone, then the person's oldest versions go until they fit. Replaces `design_limits` (adds `versions_kept`, `version_gap_seconds`), `save_design` and `my_design_space` (adds `version_bytes`); new `design_versions(id)`, `get_design_version(id, saved_at)`, `my_data_part_design_versions`. `test/test_design_versions.py`: the gap at 0.9×/1.1×, the newest 20, oldest-first room, nobody else.
- `test/test_database.py` (`python3 -m unittest discover -s supabase/test`, run by CI): a throwaway PostgreSQL with `test/auth_stub.sql` (Supabase's roles, `auth.users`, `auth.uid()` and its default grants), then every migration, acting as signed-in people, as nobody and as the owner. Fails, never skips, when PostgreSQL's server programs are missing.
- `functions/bug-report/index.ts` + `migrations/20261111000000_bug_reports.sql`: Report a bug without a GitHub account (one file, no imports, deployed with Verify JWT off). Only the app's pages may send; the report becomes an issue in the PRIVATE repo `BUG_REPORT_REPO`, its design a file there the issue links to; titles, bodies and designs are capped (0.9×/1.1× tested); `@` is broken so nobody is pinged. `bug_report_allowed(sender)` (service_role only): 5 an hour per sender, 200 a day in all, the log kept a day; a sender is SHA-256 of `BUG_REPORT_SALT|address`, never the address. Secrets: `GITHUB_BUG_TOKEN` (fine-grained, that repo only, Issues + Contents), `BUG_REPORT_REPO`, `BUG_REPORT_SALT`. Not deployed until Ben sets it up; the app's `BUG_REPORT_SERVICE` (packages/ui bug-report.ts) stays "" until then. Tested by `packages/account/test/bug-report-function.test.ts` (fake GitHub and database) and `test/test_bug_reports.py`.
