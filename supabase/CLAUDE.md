# Accounts database

The optional accounts' database (Supabase: PostgreSQL with row level security). Designs are never stored here. Read with the root CLAUDE.md; the app side is `packages/account` and `apps/fission/src/account.ts`.

- `migrations/`: the schema, applied in name order by the Supabase CLI (`supabase db push`). Never edit a migration that has been applied to the live project; add a new one. Every public table gets row level security and starts by revoking Supabase's default grants to `anon` and `authenticated`; grants are column by column where a person may change anything.
- `migrations/20261104000000_accounts.sql`: `profiles` (the email choice, unticked by default, with the time it last changed as the consent record), `plans` (free/pro/team, written only by the server), `ai_allowance` (never read by the browser; `my_allowance()` gives the whole percentage used, rounded down, at most 100), `my_data()` (everything kept about the person), `delete_my_account()` (removes the sign-in and every row through the foreign keys), and the trigger giving a first sign-in its rows.
- `migrations/20261105000000_payments.sql`: Pro through Stripe. `billing` (a person's Stripe customer, subscription and its status; never read by the browser), `plans.cancels_at_period_end`, and four functions only `service_role` may run: `billing_customer`, `link_stripe_customer` (keeps the first if two checkouts race), `set_plan_from_stripe` (active, trialing and past_due are Pro, every other status free, Team untouched; false for an unknown customer) and `forget_billing`. `delete_my_account` now refuses while a Stripe customer is linked (the billing function deletes it at Stripe first), and `my_data` shows the Stripe link.
- `functions/billing/index.ts`: the only code that talks to Stripe (a Supabase Edge Function, one file with no imports so it can be pasted into the dashboard; deployed with Verify JWT off, since each route checks the caller itself). Routes `checkout`, `portal`, `delete-account` (Stripe customer deleted first, so nothing is charged after) and `webhook` (signature checked, the subscription read back from Stripe rather than trusted from the event, a subscription with no account left is cancelled). TEST MODE ONLY: a live key or live event is refused unless the secret `ALLOW_LIVE` is `yes`, which waits for the lawyer's review and the hosting move. Secrets: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_MONTHLY`, `STRIPE_PRICE_YEARLY`, `STRIPE_COUPON_FIRST_YEAR`. Tested in node by `packages/account/test/billing.test.ts`.
- `migrations/20261105120000_my_designs.sql`: `designs` (each person's kept designs: file text up to 5 MiB, a picture up to 32 KiB as an image data: address, the workspace tag, revision), closed to the browser except through `save_design` (sizes, the person's space of 200 designs and 20 MiB, the revision last seen; answers saved/changed/gone/too-big/full/off), `my_designs`, `get_design`, `delete_design`, `delete_my_designs`, `my_design_space`; `profiles.keep_designs` (on by default); `my_data()` rebuilt from parts (payments' Stripe link is now `my_data_part_payments()`): every `my_data_part_<name>()` made by the migrations' owner adds its keys, so a later feature adds a part instead of replacing it. `test/test_designs.py`: other people can't list, read, change or delete, 0.9×/1.1× of every limit, two devices, the parts.
- `migrations/20261105180000_design_versions.sql`: `design_versions` (account features 2: the copy each `save_design` replaces, kept when it differs and the newest is 10 minutes older, the newest 20 per design, deleted with the design). Versions count in the 20 MiB but never cost a save: whether a save fits is decided by the designs alone, then the person's oldest versions go until they fit. Replaces `design_limits` (adds `versions_kept`, `version_gap_seconds`), `save_design` and `my_design_space` (adds `version_bytes`); new `design_versions(id)`, `get_design_version(id, saved_at)`, `my_data_part_design_versions`. `test/test_design_versions.py`: the gap at 0.9×/1.1×, the newest 20, oldest-first room, nobody else.
- `migrations/20261112140000_design_versions_session_end.sql`: replaces `save_design` again (after `20261111150000_design_versions_server_time.sql`, which made the server's clock decide): the copy a save replaces is also kept when it stood in the account for the 10-minute gap before this save, so the state a session ended in is a version when the next session saves over it (issue #628 item 3). Nothing else changes. `test/test_design_versions_session.py`: the week-later case worked by hand, 0.9×/1.1× of how long the copy stood.
- `migrations/20261111120000_shares.sql`: sharing links (community C2a). `shares` (a frozen copy of a design as shared: file text up to 5 MiB, picture up to 32 KiB; its id, a random UUID, is the link; `off_at` when turned off, the copy emptied then; `removed_at` when taken down after a report), `share_reports` (kind from a fixed list, reason up to 1,000 characters, reporter forgotten when they delete their account; no foreign key to the link, so a report outlives it). `share_switch` (one row, sharing off for everyone until the owner turns it on: `set_sharing`, server only; while off, nothing shares, opens or reports, and people can still turn their own links off). Functions: `share_design` (signed in: 50 links on, 20 MiB, 20 new a day counting turned-off ones; answers shared/too-big/full/daily/held/off), `open_share` (anyone, never says who shared it; null for a link off, taken down or never made), `my_shares`, `unshare`, `report_share` (anyone; kept/gone/own/held/enough/bad/off: at most 5 from one signed-in person a link and 50 a day across links, 200 signed-in a link, signed-out reports their own 20 a link so they can't crowd out real ones; never the sharer's own; the id sequence closed to the browser), `remove_share` (server only, until C5's review list), `my_data_part_shares`. `test/test_shares.py`: anyone opens, nobody lists or turns off another's, every limit at 0.9×/1.1×, reports kept and capped, Download my data and deleting the account.
- `migrations/20261111130000_display_names.sql`: profiles, first piece (community C6): `display_names` (the only thing a profile holds; `name_key`, from `display_name_key`, is unique: a short form of the Unicode confusables skeleton, accents off, lower case, letters and digits only, Cyrillic and Greek look-alikes and 0/1/i/3/4/5 folded to Latin letters, so look-alikes are one name), `blocked_name_words` (server only; compared folded; a name may not be, begin or end with one, or hold one marked `anywhere`; PLACEHOLDER list of names passing as SpindleLabs until C5), `display_name_script_ok` (one writing system a name, so no mixing Latin with look-alike letters). `set_display_name` (3 to 30 characters, letters of one writing system, digits 0-9, spaces, `_ - .`, already in NFKC form, starting and ending with a letter or digit, at least 3 letters and digits, once a week; answers saved/bad/blocked/taken/too-soon/held), `my_display_name`, `display_name_key`, `reset_display_name` (server only), `my_data_part_display_name`. Nothing shows a name to others yet (C3 adds that). `test/test_display_names.py`.
- `migrations/20261111160000_moderation.sql`: moderation, first piece (community C5a), all server only (service_role). `share_reports.reviewed_at`; `moderation_log` (every decision: what, about which link or person by id, who decided, why; no foreign keys, so it outlives both); `account_holds` (no new links or name changes until `until`, null for closed; enforced by triggers on `shares`, `display_names` and `share_reports`, which those functions answer as "held"; turning links off still works); `takedown_claims` (copyright claims, open/upheld/rejected). Functions: `review_queue` (links with open reports, most reported first), `decide_share` (take-down/put-back/dismiss, marks the reports looked at), `moderate_name`, `hold_account` (optionally takes every link down), `end_hold`, `record_claim` (takes the link down while it is looked at; null for a link that never was; `took_down` says whether this claim is what took it down), `decide_claim` (rejecting puts the link back only when a claim took it down and no other claim on it is open), `my_data_part_moderation` (the person's hold and the decisions about them, never who decided or the note). `test/test_moderation.py`.
- `migrations/20261111170000_likes.sql`: likes (community C7a). `share_likes` (one per person per link, key `(share_id, user_id)`; never read by the browser), `like_actions` (each like and unlike for the daily cap, a person's day-old rows deleted on their next one). Functions: `like_share` (liked/already/gone/own/held/daily/off; never your own link; held accounts refused by moderation's trigger on the table), `unlike_share` (unliked/not-liked/daily; works while sharing is off or the person is held), `like_count` (anyone; null for a link off, taken down or never made, or sharing off; likes from accounts held now don't count), `i_like`, `like_limits` (300 changes a day), `my_data_part_likes`. Turning a link off deletes its likes (trigger on `shares`). `test/test_likes.py`.
- `migrations/20261112030000_library.sql`: the public library, first piece (community C3a1), behind `share_switch`. `library_entries` (title up to 100, description up to 2,000, licence one of CC-BY-4.0/CC-BY-SA-4.0/CC-BY-NC-4.0/CC0-1.0, up to 8 tags of a-z 0-9 -, a picture up to 32 KiB, state uploading/live/off, `removed_at` for a takedown, a full-text `search`; never read by the browser). The file is in Storage's PRIVATE bucket `library` (5 MiB a file, application/json) as `<entry id>.spindle`, never the account id; Storage policies on `storage.objects` (through `library_may_upload`/`read`/`delete`) let a person upload once, within the hour, to their own waiting entry while sharing is on and they aren't held (no update policy, so no overwrite); a signed-in person read (make a download link for) a public entry, and the author their own; only the author delete. Functions: `begin_publish` (ready/bad/full/daily/held/off: 50 entries live or waiting, 10 a day counting turned-off ones), `finish_publish` (live/missing/too-big/full/gone/held/off: 50 MiB of the person's files in the bucket, live or not, until they delete them), `unpublish`, `browse_library` (anyone, newest first, words and a tag, a page of at most 48 after a cursor; null while off; never an account id, the author's display name only), `library_entry`, `my_library` (with each file's bytes, so the app deletes an off entry's file), `library_limits`, `my_data_part_library`. A held author's entries are hidden. Storage's test tables are in `test/auth_stub.sql`; `test/test_library.py`. Still to do (C3a2): reports, the review list and takedowns for entries, likes on entries, and deleting a person's files from the bucket when their account is deleted (the rows go with the account; the files then can't be read by anyone, but take space).
- `functions/moderation/index.ts` + `review/` (community C5b): the moderators' review page. `review/serve.mjs` serves `index.html`, `review.js` and `review.css` on 127.0.0.1:8765 only (`node supabase/review/serve.mjs`), and `review/build.mjs <folder>` writes the same page as plain files (the policy in the page, `config.json` beside it) that the mirror (SpindleLabs-app.github.io's deploy) publishes at https://spindlelabs-app.github.io/review/ for a moderator with no terminal (Ben's school laptop, 2026-11-11; `review.js` refuses to run inside a frame, since Pages can't send frame-ancestors; the mirror also serves an app copy, so a script injected into that copy could reach the page: the sign-in and the list stay the real lock); the page is never part of the app or its build (Supabase serves no HTML from functions without a custom domain, and the app must not carry it), with a content security policy allowing only its own script, data: pictures and the account service, and everything from people put on the page as text. It signs in with Google as the app does (PKCE; the service's redirect list needs `http://localhost:8765/` and `https://spindlelabs-app.github.io/review/`, back to the page's own address), keeps the token in the tab only, and asks the function for everything. The function (one file, no imports, Verify JWT off) checks every request on the server: the review page's origin (`REVIEW_ORIGINS`: those two, never spindlelabs.app), the sign-in with the sign-in service, then the account id against the secret `MODERATORS` (`<account id>=<name>` pairs; unset or any malformed entry locks everyone out); nothing of the request is read before that. The record's moderator name is the list's, never the request's. Then only the C5a functions and plain reads as service_role, every id a checked UUID and every decision with a note (1 to 2,000 characters); `notice` gives the owner's email only for a link that is down, for the takedown email the moderator sends by hand (its words in `review.js` `noticeText` are a PLACEHOLDER until the legal check). A held or closed account that deletes itself starts clean when it signs in again (nothing kept to recognise it; a hash of the Google id waits on legal items 27/28). Tested by `packages/account/test/moderation-function.test.ts` (fake sign-in service and database: who may call, every check at its edges), `test/test_moderation.py` (every table and column the function reads, taken from its source, selected as service_role; deleting a closed account) and the browser check `apps/fission/e2e/review-page.mjs` (not in the built app; lists, opens, takes down with a note; a report's HTML shown as text under the real policy; a non-moderator sees only that).
- `test/test_database.py` (`python3 -m unittest discover -s supabase/test`, run by CI): a throwaway PostgreSQL with `test/auth_stub.sql` (Supabase's roles, `auth.users`, `auth.uid()` and its default grants, and Storage's `storage.buckets` and `storage.objects`), then every migration, acting as signed-in people, as nobody and as the owner. Fails, never skips, when PostgreSQL's server programs are missing.
- `functions/bug-report/index.ts` + `migrations/20261111000000_bug_reports.sql`: Report a bug without a GitHub account (one file, no imports, deployed with Verify JWT off). Only the app's pages may send; the report becomes an issue in the PRIVATE repo `BUG_REPORT_REPO`, its design a file there the issue links to; titles, bodies and designs are capped (0.9×/1.1× tested); `@` is broken so nobody is pinged. `bug_report_allowed(sender, bytes)` (service_role only; `20261111010000_bug_report_limits.sql` after the 2026-11-11 security review): 5 an hour and 15 a day per sender, 200 a day and 100 MiB of designs a day in all, rows deleted on the first call after they are a day old; a sender is SHA-256 of `BUG_REPORT_SALT|address`, the address from cf-connecting-ip else the last x-forwarded-for entry, IPv6 by its /64 (`senderAddress`), never the address itself. The request is never read past `MAX_REQUEST_BYTES`; the body is measured after `quiet` (& and @ broken); the design's name is escaped in the issue. `test/bug-report-review.test.ts` keeps the review's cases. Trusting cf-connecting-ip is safe only if Cloudflare sits in front of the function and replaces it: each report logs which address headers came (`addressHeaders`, names only) so the first live report confirms it; if honest reports show no cf-connecting-ip, drop it from `senderAddress`. Secrets: `GITHUB_BUG_TOKEN` (fine-grained, that repo only, Issues + Contents), `BUG_REPORT_REPO`, `BUG_REPORT_SALT`. Deployed by Ben 2026-11-11 (private repo SpindleLabs-app/bug-reports); the app sends to it from its own pages (packages/ui bug-report.ts `BUG_REPORT_SERVICE`). Its page list (`APP_ORIGINS`) must match the app's `BUG_REPORT_ORIGINS` (checked by packages/ui test/bug-report.test.ts). The privacy page's Reporting a bug item describes it. Tested by `packages/account/test/bug-report-function.test.ts` (fake GitHub and database) and `test/test_bug_reports.py`.
- `migrations/20261113120000_print_log.sql`: the print log (account features 5). `print_log` (key `(user_id, id)`, the id a UUID made in the browser: when made, the design's name up to 100, the slicer's choices in words up to 200, grams and minutes or null, result waiting/well/failed, a problem from a fixed list only when failed, a note up to 500, `updated_at` from the device that changed it, never later than now); `profiles.keep_print_log` (on by default) and `profiles.print_log_since` (when the account's copy last started afresh: keeping turned back on, or the copy deleted; a browser then counts nothing it saw before as deleted). Functions: `my_print_log` (keep, since and the prints, newest made first), `save_prints` (at most 50 a save, every print checked by `print_log_valid` before any is written; a kept print replaced only by a later change, `older` otherwise; 500 a person, `full` past that; answers done/invalid/off), `delete_prints` (at most 500 ids), `set_keep_print_log` (off deletes them), `delete_my_print_log`, `print_log_limits`, `my_data_part_print_log`. `test/test_print_log.py` (22 tests: `since` starting afresh, nobody else's, the later change, a clock ahead, every limit at 0.9×/1.1×, off, Download my data, deleting the account).
- `migrations/20261113180000_friends.sql`: friends by profile ID (account features 6). `friend_codes` (a person's ID, 10 characters of Crockford base 32 from a random UUID's random bytes; having one means Friends is on; needs a display name), `friend_requests` (from, to, the ID typed, declined; gone after 30 days), `friendships` (one row a pair, smaller id first), `friend_blocks` (kept while Friends is off), `friend_tries` (IDs typed, kept a day for the 20-a-day limit). Nobody is ever searched for or listed: `send_friend_request(typed ID)` (sent/friends/waiting/already/self/not-found/bad/blocked/off/held/too-many/full; a request to someone who blocked the asker is kept but never shown, so blocks are never told; asking back is a yes), `my_friends` (display names only, the asker sees only the ID typed until accepted, never an account id), `set_friends` (off deletes the ID, friends and requests, keeps blocks), `new_friend_code`, `accept_friend_request`, `decline_friend_request` (the asker still sees it waiting), `cancel_friend_request`, `remove_friend`, `block_friend` (a friendship's or an incoming request's id), `unblock_friend` (deletes requests sent while blocked), `friends_limits` (200 friends, 20 waiting, 20 tries a day, 30 days), `my_data_part_friends`. `test/test_friends.py` (ID randomness per place, reading typed IDs, every answer, nobody else's rows, every limit at 0.9×/1.1×, Download my data, deleting the account, seeded four-person sessions against a model).
- `migrations/20261113190000_closed_counters.sql`: closes the bug report log's id counter to the browser (Supabase's default grants leave every new sequence open; moved to its end, every later insert fails). `test/test_sequences.py` checks every sequence in `public` for both browser roles, so a migration that adds a table with a counter must revoke it.
