# MCP server (beta)

Contents of `packages/mcp` (`@fission/mcp`): a local MCP server so an AI client (Claude Desktop, Claude Code) can open, read, measure, build and save SpindleLabs designs. Beta: not part of the app, not shipped on the web, tool set versioned by `TOOLS_VERSION` (bump it whenever a tool is added, removed or changes what it takes or gives). The rules are in packages/CLAUDE.md and the root CLAUDE.md; the assistant's rules in docs/ai.md hold here too (commands only, never geometry worked out here, never a machine).

Run: `node --experimental-strip-types --no-warnings packages/mcp/bin/main.ts --folder <folder>` (Node 22.6 or newer, after `npm install` at the repo root; `--folder` any number of times, each an absolute path that is there). The tools read and write only inside those folders, judged by where a path really is (links followed), and answer in the same words for anything outside, there or not; with no `--folder`, nowhere (`Files.allowed`, `nodeFilesIn`, `foldersFrom` in `bin/node-files.ts`, `insideFolders` in `src/session.ts`). stdout carries only protocol lines.

- `src/protocol.ts`: the MCP wire protocol by hand (no SDK): newline-delimited JSON-RPC 2.0 over stdio, `initialize` (versions `PROTOCOL_VERSIONS`, newest when the client asks another), `ping`, `tools/list`, `tools/call` (a refusal or a thrown tool is a tool error with `isError`, never a dead server), notifications unanswered; `handleLine` never throws.
- `src/args.ts`: `argsProblem` checks a tool's arguments against its small schema (unknown keys, types, limits) before anything runs; `argsSchema` the JSON schema tools/list shows.
- `src/session.ts`: `Session`, the tools, one design open at a time on one `BodyCache`: `open_project` (plain or zip `.spindle` through open-format's `readAny`, then core's `projectFromJson` with Design's `readDesignDocument`; refused over `MAX_PROJECT_BYTES` before reading), `new_project`, `describe_design` (timeline with each item's state, marker, bodies by browser number), `measure_body` (the kernel's `BodyView`: volume, area, bounds; mass from a density up to `MAX_DENSITY`), `export_stl` (Design's `endStls` and `joinStl`, then the kernel's `check_solid` on the bytes written), `save_project` (core's `projectToJson`), and Design's own commands as tools (`COMMAND_SPECS`: `DESIGN_COMMANDS` less export_stl, extrude_sketch also taking `sketch` by name; schemas from core's `commandSchema`, run by `documentFor`, rebuilt by `rebuildTimeline`, refused with nothing changed when an item that built fails or the new item fails). A file's own words in an answer (the project's name, an item's reason, why a file won't open) go through `fileWords`: one line of at most `FILE_WORDS` characters, since an AI client reads them and a design from someone else may hold anything. Writes never replace a file unless `overwrite`; paths must be absolute (`isAbsolute`, any system). Combine is left out until it is public.
- `src/info.ts`: the server's name, version and instructions. `src/index.ts`: exports.
- `bin/node-files.ts`: the real file system for the tools (Node only): a write never goes through a link (the tools check the name's ending, so the file written must be the one with that name), and a new file is made only where nothing is, in one step (a link pointing nowhere counts as something).
- `bin/main.ts`: the stdio entry (Node only, outside `src` so the browser type check skips it): `nodeFiles`, the kernel from packages/testing's `nodeKernel`, one message at a time.

Tests (`npm test` here):
- `test/protocol.test.ts`: every bad line's error code, notifications, version choice, refusals and thrown tools as tool errors (a stand-in host).
- `test/args.test.ts`: each argument type broken, the density limit at 0.9×/1.1×, absolute paths on Linux, macOS and Windows.
- `test/session.test.ts` (real kernel): hand-worked box, cylinder and sketched rectangle (volume, area, bounds, mass, the STL's 684 bytes), every refusal changing nothing, hidden bodies and STL, save and open byte for byte and as a zip package, files that aren't projects, Ben's Combine regression file, no body left in the kernel after `close`, the command tools' schemas equal to Design's.
- `test/random.test.ts`: seeded random good and bad calls (`MCP_RANDOM_SEEDS`, `FISSION_SEED` replays one): every call answers, every listed body measures, no body left in the kernel.
- `test/files.test.ts`: `nodeFiles` on a real temporary folder (a link is never written through, a link pointing nowhere is "there"). `test/file-words.test.ts`: a hostile file's name and descriptions come back as one short line.
- `test/stdio.test.ts`: a whole session over stdio in a child process, a bad line in the middle, a clean exit.
