# Storage

Contents of `packages/storage`; the rules are in packages/CLAUDE.md and the root CLAUDE.md. Keep this list current when you add or change a file here.

- projects kept in the browser. `store.ts` (`projectStore(kv, readers, now)`: list, open, save, remove; each project is `project/<id>`, its exact .spindlelabs.json text, and `summary/<id>`, name, save time, save number (`order`, counted across every project in one `order` entry, so the list is in the order saves happened whatever the clock said, real-use hunt B5, `test/clock-order.test.ts`, and the saving autosave's `writer` id when it names one); open goes through `projectFromJson`; a save given the save time it expects is refused with `ProjectChangedError` when another tab saved since; the check and both writes are one `KeyValue.update`, one readwrite IndexedDB transaction, so no other tab's save lands between them and a killed tab leaves both entries or neither, real-use hunt B6/B7, `test/store-atomic.test.ts`; `storedCopy(store, project)` finds the stored project holding exactly an opened one, compared as read, so Open reuses it instead of storing another copy, real-use hunt B3, `test/stored-copy.test.ts`) over the `KeyValue` interface in `key-value.ts` (`memoryKeyValue()` for unit tests); `indexeddb.ts` is the thin browser adapter, checked by `apps/fission/e2e/storage.mjs`; `localStore(readers)` is the two together; `autosave.ts` (`startAutosave`: saves a quiet moment after each `changed()` (`refused()` once a save was refused as another tab's), one save in flight, reports "saving"/"saved"/error; given `storedAt`, each save expects the store to hold its last read or write, so a stale tab says "changed in another tab" instead of overwriting, and its `leaving()` asks rather than journal a change that would be put back over the other tab's, while its `finish()` (Open) stores that change as a separate `fromAnotherTab` project behind the newer work and returns its name (round 2 hunt A5, `test/two-tabs.test.ts`); tested on a fake clock; `leaving()`, called by the shell when the page is hidden, reloaded or closed, writes changes not stored yet to the journal and starts the save at once, false when it can't keep them so the page asks before going); `unsaved.ts` (the unsaved-changes journal in localStorage, `panoshape.unsaved/<id>` holding `@<ms>` (when it was written; `@<ms>!` for one recovery couldn't store, which no tab saves over), then `~<ms>` when the tab knew it (the save time of the stored state the change was made from), then `#<writer>` (the autosave that wrote it, `startAutosave`'s random `writer`, which its saves store too), a newline and the file text, removed once the store holds that state or newer; `recoverUnsaved` puts entries back before the app lists projects, skipping one older than the stored project's save time (the time its state was read); one naming the state it was made from goes back only over that state (`store.save`'s `unchangedSince`), and over any other, a stale tab's change, is stored as a separate project named `fromAnotherTab` ("Box (from another tab)") listed behind every other (`save`'s `behind`), so the newer work still opens, and a save never removes such an entry (real-use hunt S1, `test/two-tabs.test.ts`); but a store whose last save is the entry's own writer's (the page reloaded while Saving…, its save finished by the browser after the page had gone) is no other tab's work, so the entry goes back over it, or just goes when that save is newer than it, and an entry holding exactly what the store holds just goes (merge-queue CI, `test/own-save.test.ts`, seeded one-tab page lives against a model); an entry from a newer SpindleLabs (`NewerFormatError`, core) is moved to `panoshape.unsaved-newer/<id>` (`NEWER_PREFIX`), out of this build's autosave's way, said once, and put back by a build that reads it (real-use hunt S2, `test/unsaved.test.ts`); `keptEntry` gives an entry recovery couldn't store (storage full), which the app opens instead of the older stored state, with an autosave started `fromKept` that owns the entry: it saves over the older state once there is room and journals each state still marked kept until then (real-use hunt B1, `test/kept-entry.test.ts`); seeded page-life runs in `test/unsaved.test.ts`, two tabs sharing one store and journal in `test/two-tabs.test.ts`, review repros in `test/review-repros.test.ts`). Workspaces call `ctx.projectChanged()` after writing `ctx.project`; the shell autosaves on it.
- `persist.ts`: `keepStorage(navigator.storage)` gives a function that asks the browser once to keep the store (`persist()`), so projects aren't cleared when space runs low; the shell calls it after the first save of the user's own work, never on load (real-use hunt B3, `test/stored-copy.test.ts`).
- `reopen.ts`: the reopen guard (audit S2): the `panoshape.opening` mark in localStorage names the project a tab is opening until it settles (SETTLED_MS after showing); a visit finding it skips that project once. `check()` first asks the other tabs over a BroadcastChannel (`OpeningChannel`), so a tab still opening it answers within ASK_MS and isn't taken for a freeze (real-use hunt A3); `finished()` clears only the tab's own mark; `putAway()`/`back()` (page hidden or frozen, then shown again) take the tab's mark down so a phone killing a put-away tab leaves none (D1), putting it back while the project is still opening. Tested on a fake clock and bus in `test/reopen.test.ts` (seeded one-tab and two-tab runs against a model); browser check `apps/fission/e2e/reopen.mjs`.
- `projects.ts` (U6a; round 2 hunt A2, A3): for File > Projects in this browser. `bringForward(store, id, at)` stores a project opened from the list again as it is, same save time, new save number, so a reload opens it (false when another save changed it since, which it leaves alone; throws on storage full); `rename(store, id, name)` renames a stored project (trimmed; refuses empty or over `MAX_PROJECT_NAME` = 100; `ProjectChangedError` when another save got there first); `forget(store, journal, id)` deletes a project and its journal entries, without which the next visit's recovery would bring it back. `test/projects.test.ts` (hand-worked cases, storage full, a deliberate break, 5 seeded sessions × 1,000 steps of saves, renames, opens from the list, deletes and new projects against a model).
- `versions.ts` (missing basics 3b): earlier versions. `versionedStore(store, kv, readers)` (what `localStore` gives) keeps, on each save, the state it replaces as `version/<id>/<ms>` (its exact text, `<ms>` its save time) when the newest version is at least `VERSION_GAP_MS` (10 min) older, the newest `VERSION_LIMIT` (20); a save of the same state keeps none; `versions(id)`, `openVersion(id, at)`; `remove` takes the versions too. Versions never cost a save: one that can't be written is passed over, and a save refused as storage full (`storageFull`) gives up that project's versions and is tried once more. `test/versions.test.ts` (hand-worked times, the 10-minute boundary, the newest 20, storage full, 5 seeded sessions × 1,000 saves against a model).

- `undo-steps.ts` (step 89): each kept project's undo steps, kept beside it so a reload carries on where it was; never in the file, a shared copy or the account. `steps/<id>` (`encodeSteps`: format 1, the present's index, each step's snapshot, label, merge key and time) and `steps-at/<id>` (when written); past `STEPS_CHAR_LIMIT` (8 million characters of snapshots) the oldest steps go, then the redo steps furthest away, never the present; only the `STEPS_PROJECTS` (10) projects written most recently keep theirs, the one just written always among them (save/load hunt C8: a clock set back). `decodeSteps` reads anything else as none; `alignSteps` lines kept steps up with the project as it opens (its present, or its last step that matches, the later ones a redo away; none when changed in another tab). Never costs a save: a failed write forgets that project's steps, a save refused as storage full is retried once this project's versions and steps are forgotten, and only if it is still refused once every project's steps are forgotten too (save/load hunt C7), and `remove` forgets the project's. On the store as `store.steps`. `test/undo-steps.test.ts` (the limit by hand at its boundary, damaged text, storage full, a real history put back, 20 seeded sessions against a model).
- `store.ts` summaries (U6a) also carry `touched` (when the project was last saved or opened) and `works` (workspaces with work in them, from core `workspacesWithWork`), for the home screen.
