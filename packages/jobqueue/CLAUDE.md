# Job queue

Contents of `packages/jobqueue`: the job queue for school makerspaces (steps and rules: `docs/progress/queue.md`). Its own package and switch so it could be split out later; no workspace imports it yet. It depends on `@fission/print` (build area, print check, supports hint, slicing) and `@fission/core` (the kernel's calls). Keep this list current when you add or change a file here.

- `queue.ts` (Q1): the queue's rules as plain functions on plain data, no page, no network, no clock. `newQueue(machines)`, `withStudent(queue, id, displayName)` (the only personal data: a name the teacher types); `apply(queue, action)` for every move (send, check, approve, return, withdraw, move, start, finish, requeue), never throws, never changes the queue given, and refuses with a kind (`bad-input`, `not-found`, `not-allowed`, `wrong-state`, `machine-busy`) and a detail; `placeOf` (place, jobs and known minutes ahead, unknown ones counted apart); `studentView` (a student's own jobs and the queue lengths only, never another student's name or file); `totals` per machine and per student over every finished run (a failed run put back in the queue still counts), recorded use else the estimate, with how many came from estimates or are unknown; `QUEUE_LIMITS`, `refusalWords`, `STATE_WORDS`. `test/queue.test.ts`: hand-worked sessions, every refusal, 0.9×/1.1× of every limit, privacy of the student's view, 200 seeded sessions against a table model.
- `check.ts` (Q2): the automatic file check. `checkPrintFile(name, bytes, { kernel, choices?, material? })` (an STL through the P1S's build area, the print check, the supports hint and the slicing engine; time and filament as the estimate) and `checkLaserFile(name, bytes, bed = KH1490_BED)` (an SVG or DXF against the bed, as it is or turned; time null, "not yet"), each a `FileCheck`: passed with `estimate`, `facts` and `notes`, or refused with one `reason`, in plain words; `bedFit`, `FIT_TOLERANCE` (1 µm), `checkAction` (the queue's check action, texts cut to the queue's limits). `test/check.test.ts`: Laser's own colours read back, hand-worked fits, 0.9×/1.1× of the tolerance, spline slack, every refusal, seeded parts near the plate's limits on the real engine against a model of the plate's rules, the answer into the queue.
- `stl.ts`: `readStl` (binary by its length, else text; corners merged; `openEdges`), `binaryStlOf`, `isBinaryStl`. `test/stl.test.ts` (the box helpers are in `test/meshes.ts`).
- `svg.ts`: `readSvg` (a small XML reader of its own; shapes, paths, transforms, style sheets, units) to a `DrawingRead` (width, height, `slack`, shapes per layer, notes); `LASER_COLOURS`, `parsePaint`, `parseTransform`, `addPath`, `addSvgArc` (the SVG specification's endpoint-to-centre steps). `test/svg.test.ts`.
- `dxf.ts`: `readDxf` (text DXF: LINE, CIRCLE, ARC, LWPOLYLINE and POLYLINE with bulges, ELLIPSE, SPLINE, INSERT; `$INSUNITS`; colour by entity, BYLAYER, BYBLOCK; extrusion (0, 0, −1) mirrored back); `LASER_DXF_COLOURS`, `DXF_LIMITS`. `test/dxf.test.ts`.
- `box2d.ts`: the exact outer box of lines, arcs (any affine image of a circle's) and Bézier curves after an affine map; `bulgeArc`. Here only until the kernel's 2D curve library has Béziers (Vector V1). `test/box2d.test.ts` (300 seeded curves against dense sampling).
